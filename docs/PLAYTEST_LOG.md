## S09~S36 구현 후 확인 · 2026-09-23

Edge headless에서 S28의 세 균형 장치를 정상 이동/E 입력으로 작동시켜 T06을 받고 재접속 후 보유를 확인했다. S36에서는 네 전시 목표, 마지막 기록, 새 항해의 종을 순서대로 조사해 완료 화면과 `ending` 플래그/S36 완료 저장까지 도달했다. S36 완료 화면 스크린샷은 Playwright 산출물에 생성됐다. 초기 자동화는 점프 중 머리 위 발판에 착지해 조사 높이를 벗어난 문제를 발견했고, 평화 구간에서는 바닥 이동 후 조사하도록 테스트를 바로잡았다.

S09~S36 전체 장면 렌더 반복 검사는 28개 장면 모두 로드하고 pageerror/HTTP 400+가 없음을 확인했다. 전체 `npm run test:e2e`의 17개 시나리오는 각각 `ok`로 끝났지만 결과 출력 후 프로세스가 남아 강제 종료했으므로 exit 0은 미확인이다. S09~S27/S29~S35 개별 정상 완주와 수동 손 플레이는 미검증이다. 단위/콘텐츠 검사는 36개 맵과 보상 그래프를 모두 통과했지만 이를 개별 완주 증거로 대신하지 않는다.

## 방법과 경계

`tests/e2e/adventure.spec.ts`는 새 저장에서 실제 키보드로 이동·점프·공격·대화·보물을 조작합니다. 개발용 API는 위치·HP·보상 상태의 **읽기 전용 스냅샷**이며 테스트가 플레이어 위치나 보상을 직접 변경하지 않습니다. 사망/복구 등의 독립 회귀 검사는 별도 초기 저장 픽스처를 사용하므로 캠페인 완주 증거와 구분합니다.

앱 내 브라우저 스킬 연결은 `privileged native pipe bridge is not available; browser-client is not trusted`로 실패했습니다. 별도 UI 자동화의 Edge 연결도 사용할 수 없었습니다. 저장소 Playwright에서 설치된 Edge headless 실행은 가능했고, 생성된 스크린샷을 직접 열어 확인했습니다. 따라서 **도구를 통한 실제 입력 자동 플레이 + 스크린샷 육안 확인**이며 별도 손 플레이나 실제 모바일 기기 검증으로 보고하지 않습니다.

## 실제 발견과 수정

1. 타입 검사: JSON의 빈 배열에 대한 union 추론으로 `includes` 인자가 `never`가 됨. 명시적 StageRegistration 타입으로 수정.
2. CSS 로더: 불필요한 data-URL import가 Vite의 파일 경로로 해석됨. 삭제.
3. 콘텐츠 검사: 선택 상자 발판을 필수 바닥으로 분류해 높이 검사가 오탐. 필수 바닥 속성을 분리.
4. E2E: 대화나 무기 교체 입력의 다음 게임 프레임 전에 검사하여 실패. DOM/상태 변경을 기다리도록 수정.
5. E2E: 적이 플레이어 뒤에 있는데 계속 오른쪽으로 공격. 현재 적 위치에 맞춰 실제 방향키를 누르도록 수정.
6. 암초 낙하: 좌표만 옮기던 복귀 코드를 Arcade Body.reset으로 변경해 충돌 몸체도 초기화. 낙하 복귀 전용 회귀 검사 추가.
7. 회피: 최대 수평 속도가 300에 제한되어 있던 것을 회피 중 530으로 변경.
8. 보스: 보상·승리 목표·안전 체크포인트를 단일 순수 상태 전이에서 확정.
9. 세이렌: 파도/음표 투사체에 ≋ / ♪ 형태 표시. 근접 적 예고 범위를 실제 공격 범위와 같은 사각형으로 표시.
10. Windows에서 실패 trace 정리가 오래 대기하여 E2E trace는 껐습니다. HTML 결과와 실패/통과 지점 스크린샷은 유지합니다.
